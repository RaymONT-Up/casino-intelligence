# Показ на встрече: 10–15 минут

Перед встречей проверить Docker и локальную базу, затем запустить `pnpm build`
и `pnpm start`. Открыть `http://127.0.0.1:3000`: собранная версия не показывает
значок Next.js dev mode. Пароль редактора взять из локального `.env`; не выводить
его на экран и не вставлять в слайды. Проверить каталог и вход заранее.

1. Открыть каталог: пять реальных брендов, домены из iGO, дата самого источника.
   Ввести `northstar` в поиск, затем очистить его; на телефоне записи показаны
   карточками с теми же полями.
2. Открыть NorthStar: показать два факта из условий, исходный URL, время и snapshot.
   Объяснить, что «listed by iGO», «регистрация проверена» и «доступно игроку» различаются.
3. Войти в `http://127.0.0.1:3000/admin` с `ADMIN_PASSWORD` из локального `.env`.
   Сначала открыть вкладки Approved, Rejected и All: там сохранены реальные
   решения. Pending может быть пустой — это нормальное состояние после ревью.
4. Нажать Collect source. Это реальный сетевой запрос, а не смена заранее
   подготовленной версии. Если источник не изменился, интерфейс сообщает об
   отсутствии изменений; нового предложения не возникает. Если появится Pending,
   открыть сохранённый snapshot, сравнить поля и только затем принять решение.
   Не изображать изменение внешнего сайта ради эффектного показа.
5. Для воспроизводимого изменения показать `pnpm test:e2e`: тест использует отдельную
   БД и синтетические входы, проверяет pending → approve → public, reject и ошибку источника.
   Объяснить, что тестовые значения не попадают в настоящую базу.
6. Показать AGENTS.md / CLAUDE.md: ограничения публикации, критерии готовности, роли.
   Реальная задача для coding agent: добавить одно проверяемое поле к существующему
   адаптеру, сначала исследовать источник, написать тест, изменить парсер, пройти gates.
7. Независимый read-only reviewer проверяет diff. Исправить замечания, запустить
   `pnpm verify`. Показать фактический результат, а не обещание качества.

Claude Code нужен, если фаундер хочет увидеть именно этот инструмент. Код проекта
работает без него; Codex уже может выполнять инженерные задачи. Конфигурация Claude
есть, но установка, вход и реальный запуск сессии отдельно; не заявлять, что они выполнены.
Runtime-сборщик не вызывает LLM: это осознанный выбор для двух точных полей. AI workflow
в разработке — декомпозиция, реализация, независимое ревью и проверки. Будущий LLM
для извлечения условий должен проходить отдельные evals и выдавать только предложения.

Вопросы фаундеру: кому принадлежит исходный продукт/код; какие провинции приоритетны;
есть ли партнёрские договоры и источники; кто утверждает контент; какой результат
нужен за 30/60/90 дней; кто отвечает за юридическую проверку и SEO-дистрибуцию.
